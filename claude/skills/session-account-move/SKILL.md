# 세션 계정 이동

데스크톱 앱은 Code 탭 세션마다 목록 정보 파일 하나를 계정별 폴더에 둔다. 사이드바에는 그 계정 폴더에 있는 파일만 나온다. 대화 기록 본문은 계정과 상관없는 공용 폴더에 있다. 그래서 세션을 옮긴다는 것은 목록 정보 파일을 다른 계정 폴더로 옮기는 일이다. 이 일은 `scripts/Move-Sessions.ps1`이 맡는다. 직접 파일을 옮기지 말고 스크립트를 쓴다. 보관함 목록, 임시 폴더, 경로 고쳐 쓰기, 백업을 빠뜨리지 않기 때문이다.

## 구조

- **저장소**: 계정 ID와 조직 ID의 한 쌍이다. 위치는 `%LOCALAPPDATA%\Claude-Data\claude_*\claude-code-sessions\<계정 ID>\<조직 ID>\`이고, 세션마다 `local_<세션 ID>.json`이 있다.
- **한 계정에 조직 폴더가 여러 개**일 수 있다. 세션이 하나도 없는 빈 폴더가 생기기도 한다. 계정을 고를 때는 세션이 들어 있는 저장소, 또는 `[current]`로 표시된 저장소를 쓴다.
- **대화 기록**은 `~/.claude/projects/<작업 폴더 이름>/`에 있다. 계정과 무관하므로 옮기지 않는다.
- **임시 폴더 세션**: 프로젝트 폴더 없이 시작한 세션은 계정 경로 아래의 임시 폴더(`scratch-workspaces\<계정 ID>\<조직 ID>\...`)에서 일한다. 이런 세션은 임시 폴더와 그 이름의 대화 기록 폴더를 함께 옮기고, 세션 파일 안의 경로도 고쳐 써야 한다. 스크립트가 처리한다.
- **실행 중인 앱**은 세션 목록을 메모리에 들고 있어서, 옮긴 파일을 재시작 전까지 알아채지 못한다.
- 이 구조는 앱 내부 형식이다. 앱이 업데이트되면 바뀔 수 있다. `-List` 결과가 위 설명과 다르면 옮기지 말고 사용자에게 알린다.

## 절차

스크립트는 PowerShell 5.1에서 돈다. 셸 종류와 상관없이 아래 형식으로 실행한다. 경로의 `<스킬 폴더>`는 이 스킬의 기준 폴더다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬 폴더>\scripts\Move-Sessions.ps1" <옵션>
```

### 1. 저장소 확인

`-List`로 저장소마다 세션 수, 마지막 활동 시각, 최근 제목 세 개를 본다. `[current]`가 지금 이 세션의 저장소다. 계정은 ID로만 나오므로 최근 제목으로 어느 계정인지 가려 사용자에게 보여 준다.

- "이 계정으로 가져와"는 `-To current`다. 세션이 든 다른 저장소가 하나뿐이면 그것이 `-From`이다.
- 후보 저장소가 여럿이거나 방향이 분명하지 않으면 사용자에게 묻는다.

### 2. 옮길 세션 정하기

- 기본값은 원본 저장소의 세션 전부다.
- 일부만 옮길 때는 `-List -From <저장소>`로 세션 목록을 보고 ID를 고른다. `-SessionId`에 쉼표로 이어서 넘긴다. 쉼표 뒤에 공백을 넣지 않는다(예: `-SessionId <세션 ID>,<세션 ID>`). `local_`은 붙여도 되고 빼도 된다.
- 임시 폴더를 함께 쓰는 세션(같은 임시 폴더에서 갈라진 fork 등)은 같이 옮겨야 한다. 일부만 고르면 스크립트가 건너뛰고 이유를 알려 준다.

### 3. 원본이 지금 계정일 때

가능하면 **옮겨 받을 계정에서** 실행한다. 원본 저장소가 지금 앱에서 쓰는 계정이면 앱이 실행 중인 세션의 파일을 옛 위치에 다시 쓸 수 있다.

- 이 스킬을 실행하는 세션 자신은 스크립트가 자동으로 제외한다.
- 다른 실행 중인 세션은 앱의 세션 목록 도구로 `isRunning`을 확인한다. 그런 세션은 `-Exclude`로 빼거나, 사용자에게 멈춰 달라고 한다.

### 4. 미리 보기

`-From <원본> -To <대상> -DryRun`으로 옮길 세션과 건너뛸 세션을 본다. 이 단계는 아무것도 바꾸지 않는다. 사용자가 원본, 대상, 범위를 분명히 말했으면 바로 다음 단계로 간다. 추측으로 정한 부분이 있으면 미리 보기 결과를 보여 주고 확인을 받는다.

### 5. 옮기기

같은 명령을 `-DryRun` 없이 실행한다. 스크립트는 다음 순서로 일한다.

1. 바뀔 파일을 `~/.claude/session-account-move-backups/<시각>/`에 백업한다.
2. 임시 폴더와 대화 기록 폴더를 옮긴다.
3. 세션 파일을 옮기고 경로를 고쳐 쓴다.
4. 보관함 목록을 맞춘다.
5. 옮긴 세션마다 `ok`나 `WARN`을 출력한다.

`WARN`(작업 폴더 없음)은 원래부터 폴더가 지워진 세션일 수 있으니, 원인을 사용자에게 그대로 전한다.

### 6. 재시작 안내

사용자에게 다음을 알린다.

- 앱을 **완전히 종료**하고 다시 열어야 한다. 트레이 아이콘에서 Quit을 누른다. 창만 닫으면 안 된다.
- 재시작 전에는 옮긴 세션을 열지 않는다.
- 재시작하면 지금 이 세션도 멈추지만, 다시 열어 이어 쓸 수 있다.

재시작 뒤에 확인을 맡으면 `-List`를 다시 실행한다. `WARNING: ... is in more than one store`가 나오면 앱이 옛 위치에 파일을 다시 쓴 것이다. 어느 쪽을 남길지 사용자에게 묻는다. 대상 계정에서 앱의 세션 목록 도구로 옮긴 세션이 보이는지도 확인한다.

## 되돌리기

원본과 대상을 바꿔 같은 세션을 다시 옮기면 원래대로 돌아간다. 원본 계정 쪽에 빈 보관함 목록 파일이 하나 남을 수 있지만, 앱이 쓰는 형식이라 문제없다. 파일이 깨졌을 때는 백업 폴더의 세션 파일과 `plan.txt`를 보고 복구한다.

## 스크립트가 건너뛰는 경우

| 이유 | 할 일 |
| --- | --- |
| 이 이동을 실행하는 세션이거나 `-Exclude`에 넣은 세션 | 다른 세션에서 다시 옮긴다 |
| 대상 저장소에 같은 세션 ID가 이미 있음 | 어느 쪽이 최신인지 사용자와 확인한다. 스크립트는 덮어쓰지 않는다 |
| 임시 폴더를 함께 쓰는 세션 중 일부만 고름 | 같은 임시 폴더의 세션을 모두 고른다 |
| 임시 폴더나 대화 기록이 예상 위치에 없음 | 경로가 260자를 넘어 PowerShell이 못 읽은 경우일 수 있다. 사용자에게 알리고 그 세션은 옮기지 않는다 |

## 스크립트가 건드리지 않는 것

- 계정별 세션 프리셋(`ccd-session-presets.json`), 사이드바 구역 설정. 사이드바 고정과 그룹이 세션을 따라오는지는 확인하지 않았다.
- Cowork 작업(`local-agent-mode-sessions`)
- 삭제한 세션의 흔적 파일(`deleted_*`). 원본 저장소에 그대로 둔다.
- 세션 파일 안에 남은 이전 계정의 커넥터 설정 사본. 세션 파일 내용은 그대로 옮긴다.
