# 개념 퀴즈 만들기

학습 자료를 읽고 개념을 묻는 5지선다 문제를 만든 뒤, 5문제씩 묶어서 풀고 다시 풀 수 있는 HTML 한 장으로 만든다. 문제마다 해설과 자료 속 근거 위치, 짧은 근거 인용이 붙는다. 사용자가 퀴즈를 풀며 공부하는 것이 목적이므로, 문제의 질과 근거의 정확성이 화면보다 중요하다.

화면 템플릿(`assets/quiz-widget.html`)과 빌드 스크립트(`scripts/build_quiz.py`)는 이미 검증되어 있다. 이 둘을 고쳐 쓰지 말고, 문제 데이터 JSON만 쓴 다음 스크립트로 만든다. 묶음 버튼, 아래쪽 막대의 "틀린 문제만 보기 / 이 묶음 다시 풀기 / 다음 묶음" 버튼, 묶음별 점수는 템플릿이 문제 수에 맞춰 알아서 만든다.

## 1. 범위 정하기

- **자료:** 사용자가 준 파일이나 범위를 끝까지 읽는다. 앞부분만 읽고 만들면 문제가 앞쪽 개념에 몰리고, 뒤쪽에서 정의가 바뀌는 경우를 놓친다.
  - 긴 PDF는 쪽 범위를 나눠 읽는다.
  - PDF 텍스트 추출은 위첨자·아래첨자·수식을 흩어 놓는 일이 많다(`2^n`이 "2 n"으로 나오는 식). 수식이 있는 쪽은 쪽 이미지로 원래 식을 확인한다.
- **문제 수:** 한 묶음은 5문제다. 사용자가 묶음 수(n세트)를 말하면 5 × n문제를, 문제 수를 말하면 그 수를 만든다. 문제 수는 5의 배수로 맞춰야 마지막 묶음이 모자라지 않는다. 아무 말이 없으면 2묶음(10문제)으로 하고, 자료가 길어 그만큼으로 덮기 어려우면 그렇다고 한 줄 알린다. 사용자가 묶음 크기를 따로 말할 때만 `set_size`를 바꾼다.
- **유형:** 기본은 개념 문제다. 사용자가 계산·풀이 문제를 따로 원하지 않는 한 넣지 않는다.

## 2. 섹션 나누기

자료의 실제 구조(장·절, 문서의 헤딩)를 따라 섹션 이름을 정한다. 이름에 근거 범위를 붙여 두면 사용자가 원문으로 돌아가기 쉽다. 예: "Canvas 수정하기 (129–136행)", "3. 보수의 표현".

문제는 섹션 순서대로 놓되, 한 섹션에 몰리지 않게 자료 전체에 고르게 나눈다.

## 3. 문제 쓰기

좋은 개념 문제는 외운 문장을 그대로 고르는 문제가 아니라 개념을 제대로 구분했는지를 확인한다.

- **한 문제에 한 개념:** 정의, 성립 조건, 정리, 규칙, 이유(왜 이 규칙이 있는가), 역할(누가 무엇을 맡는가), 비슷한 두 개념의 차이 같은 것 하나를 묻는다.
- **정답은 하나:** 자료로 판정할 수 있어야 한다. 해석에 따라 갈리는 선택지는 고치거나 뺀다.
- **오답 넷은 그럴듯한 오개념으로 만든다.**
  - 조건을 하나 바꾸거나 빼기(< 를 ≤ 로, "0이 아님"을 "0이어도 됨"으로)
  - 이웃 개념과 뒤바꾸기(1의 보수 ↔ 2의 보수, d|n ↔ n mod d)
  - 경계값 틀리기
  - "언제나", "어떤 경우에도"로 지나치게 일반화하기
  - 원인과 결과 뒤집기

  말이 안 되는 선택지나 "모두 옳다"는 공부에 도움이 되지 않는다.
- **길이와 말투를 고르게:** 정답만 길거나 정답만 자세하면 읽지 않고도 맞힌다. 다섯 선택지의 길이와 말투를 비슷하게 맞춘다.
- **정답 위치를 고르게:** ①–⑤에 고르게 퍼뜨리되 규칙적인 패턴(1,2,3,4,5 반복)은 피한다. 빌드 스크립트가 위치별 개수를 출력하니 확인한다.
- **해설(`e`):** 정답이 왜 맞는지와, 사람들이 잘 고르는 오답이 왜 틀린지를 함께 쓴다. 오답을 고른 사람이 해설만 읽고 무엇을 잘못 알았는지 알 수 있어야 한다.
- **근거:** 위치(`l`)와 근거 문장(`t`)을 둘 다 적는다.
  - `l`에는 자료 이름과 위치 단위까지 적는다. 예: "교재 17–18쪽", "SKILL.md 30–36행". 화면은 앞에 "근거: "만 붙인다.
  - `t`는 자료에서 정답을 뒷받침하는 짧은 문장이다. 자료와 대조할 수 있게 그대로 옮기되 한두 문장으로 줄인다.
- **언어:** 사용자가 쓰는 언어로 쓰고, 기술 용어는 그 분야에서 실제로 부르는 말을 쓴다.

### 표기 규칙

화면은 백틱만 해석하고 나머지 글자는 그대로 보여 준다. 그래서 다음 규칙을 지킨다.

- **코드와 식별자:** 백틱으로 감싼다. 예: `canvas.json`, `auto_open`. 화면에서 고정폭 글꼴로 보인다.
- **수식:** 유니코드 위첨자·아래첨자로 쓴다. 예: 2ⁿ, rⁿ − x, 2ⁿ⁻¹, aₖbᵏ + … + a₁b + a₀, aᵢ, x², log₂n.
  - `2^n`, `a_i`, `$...$`, `\frac` 같은 TeX식 표기는 화면에 글자 그대로 드러난다.
  - 빌드 스크립트는 백틱 밖의 `^`·`_` 표기를 찾으면 경고한다. 경고가 나오면 고친 뒤 다시 빌드한다.
- **빼기 부호:** 하이픈(-) 대신 −를 쓴다. 범위는 – 를 쓴다(1–10번).
- **HTML 태그:** 쓰지 않는다. 글자로 보인다.

## 4. 데이터 JSON 쓰기

```json
{
  "title": "4장 수의 표현 개념 퀴즈",
  "summary": "이산수학 4장의 정의와 정리를 다루는 5지선다 10문제(5문제씩 2묶음) 연습 퀴즈",
  "set_size": 5,
  "sections": ["1. 수와 그 성질", "3. 보수의 표현"],
  "questions": [
    {
      "s": 1,
      "q": "보수, 1의 보수, 2의 보수에 대한 설명으로 옳은 것은?",
      "o": ["선택지 ①", "선택지 ②", "선택지 ③", "선택지 ④", "선택지 ⑤"],
      "a": 3,
      "e": "정답 이유와 잘 고르는 오답이 틀린 이유",
      "l": "교재 17–18쪽",
      "t": "n비트 2진수에 더해서 2ⁿ이 되는 수를 2의 보수라고 합니다."
    }
  ]
}
```

- `title`: 페이지 제목.
- `summary`: 화면 읽기 프로그램용 한 줄 설명.
- `set_size`: 묶음 크기. 생략하면 5다.
- `s`: 섹션 번호. 0부터 센다.
- `a`: 정답 번호. 0부터 세므로 ①이 0, ⑤가 4다.
- 문제 번호(`n`)는 스크립트가 순서대로 붙이므로 적지 않는다.

## 5. 저장하고 빌드하기

- **저장 위치:** 사용자가 정한 곳에 둔다. 정한 곳이 없으면 자료 옆의 퀴즈 폴더(이미 있으면 그곳, 없으면 `퀴즈/`)에 둔다.
- **파일:** `<이름>.quiz.json`과 `<이름>.html`을 함께 둔다. JSON을 남겨 두면 나중에 문제를 고치거나 늘릴 때 다시 빌드할 수 있다.

```bash
python3 <이 스킬 폴더>/scripts/build_quiz.py <이름>.quiz.json <이름>.html
```

출력에서 다음을 확인한다.
- 문제 수와 묶음 수
- 정답 위치 분포
- `WARNING` 줄. 형식 오류는 스크립트가 멈추며 알려 준다.

대화 화면 안에 퀴즈를 바로 띄울 수 있는 하네스라면 `--fragment <조각 파일>`을 더하고, 그 파일 내용을 그대로 인라인 위젯에 넘긴다. 조각에는 문서 머리(`<!doctype>`, `<head>`)가 없고, 색은 호스트의 CSS 변수를 쓰되 없으면 기본값으로 그린다.

## 6. 확인하기

넘기기 전에 브라우저에서 HTML 파일을 열어 확인한다. 페이지 안에서 JavaScript를 실행해 볼 수 있으면 다음을 직접 눌러 본다.
- 선택지를 누르면 해설과 근거가 펼쳐지는지
- 점수가 바뀌는지
- "틀린 문제만 보기", "다시 풀기", 묶음 이동이 동작하는지
- 화면 글자에 `^`·`_` 같은 표기가 남지 않았는지

수식이 있다면 해당 부분을 확대 캡처로 직접 본다. 브라우저를 쓸 수 없는 환경이면 빌드 출력만 확인했다고 사용자에게 밝힌다.

하네스별 차이:
- **Claude Code (데스크톱 앱):** 브라우저 창은 세션 작업 폴더 밖 파일의 스크립트를 실행하지 않고 정지 화면만 보여 준다. 작업 폴더 안에 임시 복사본을 두고 `file://`로 열어 확인한 뒤 복사본을 지운다. 인라인 위젯을 처음 쓸 때는 위젯 안내부터 불러온다.
- **Codex:** 인라인 위젯이 없으므로 HTML 파일 경로를 알린다.

## 7. 알리기

사용자에게 다음을 짧게 알린다.
- 만든 파일 경로
- 문제 수와 묶음 구성
- 섹션별 범위
- 확인한 내용

정답표는 따로 늘어놓지 않는다. 사용자가 풀기 전에 정답을 보게 되기 때문이다.
